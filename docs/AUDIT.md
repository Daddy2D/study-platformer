## 1. Что это и как запускается

- Учебный 2D-платформер на Canvas, чистый JS, без сборки. Три страницы: игра (`index.html`), редактор (`editor.html`), настройки (`settings.html`).
- Запуск: открыть HTML файлом, либо `python -m http.server 8000`. Без сервера работают не все браузеры (спрайты/`localStorage` при `file://`).
- Состояние: `.git`, один коммит `123404b chore: initial commit`, ветка `main`, рабочее дерево чистое.
- Артефакты в корне: `История развития.txt` (3 заметки владельца), `Пак_уровней(20.11.26).rar` (архив того же пака).

## 2. Архитектура и загрузка

Порядок `<script>` в `index.html` — это и есть граф зависимостей, всё лежит в глобальной области:

```
settings.js
levels/level1..8.js, levels/levels-list.js
js/storage.js  js/sound.js  js/canvas.js  js/sprites.js  js/input.js
js/world.js  js/player.js  js/enemies.js  js/boss.js  js/effects.js
js/progress.js  js/render.js  js/game.js
```

Жёсткие зависимости на этапе загрузки (нарушение порядка = падение):

| Файл | Что требует при загрузке |
|---|---|
| `levels/levels-list.js` | `LEVEL_1..8` |
| `js/world.js` | `LEVELS`, `LEVEL_NAMES`, `LEVEL_BIOMES`, `LEVEL_BOSS_TYPES` |
| `js/player.js` | `SETTINGS` |
| `js/sound.js` | `getSoundEnabled()` из `storage.js` |
| `js/render.js` | `canvas`, `SETTINGS.cloudCount` |
| `js/game.js` | всё остальное, при инициализации читает URL |

Остальные вызовы (`playSound`, `spawnParticles`, `recordLevelAttempt`, `resetEffects`, `createBoss`) происходят уже в рантайме, поэтому порядок не ломают.

`editor.html` грузит `settings.js` + уровни + `storage.js` + `editor.js`. `settings.html` — `settings.js` + уровни + `storage.js` + `settings-page.js` (без `progress.js` — не нужен).

Движок: фиксированный шаг 60 FPS, аккумулятор, не более 5 шагов за кадр, `delta` ограничен 100 мс. Холст фиксированный 960×540, растягивается CSS.

## 3. Состояния и экраны

`gameState`: `menu` | `levels` | `custom` | `stats` | `playing`.

Наложения поверх `playing`: `paused`, `gameOver`, `gameFinished`, `levelComplete` (+ таймер перехода 180 кадров). Каждый экран пересобирает `uiButtons` в `rebuildUi()`; кнопки рисуются на канвасе и обрабатываются мышью/клавиатурой (`uiIndex`, `↑↓←→`, `Enter`, клик).

Переходы уровня: `completeLevel()` → результат в `lastLevelResult` → через 180 кадров `loadLevel(index+1)` либо `gameFinished`.

URL-параметры: `?level=<n>` (готовый, с нуля), `?play=<id>` (свой), `?test=1` (проверка из редактора, кнопка «Вернуться в редактор»).

Особенности:
- готовый уровень даёт продолжение по цепочке `BUILTIN_LEVELS`;
- свой и тестовый — одиночный уровень (`gameLevels = [level]`), рекорды не пишутся;
- «Играть снова» на финале для готовых начинает с уровня 1.

## 4. Механики

### Игрок
- Размер 40×40, ускорение 0.7, трение 0.88, макс. скорость 5, прыжков 2 (`maxJumps`), гравитация 0.6, сила прыжка −13, отскок от врага −9.
- Падение ниже уровня больше чем на 64 px — потеря жизни.
- В воздухе после схода с края остаётся один прыжок.
- Лестница `H`: `W/S`/`↑↓`, скорость 3, прыжки не тратятся; прыжок со лестницы работает.
- Покачивание при беге и мигание после урона — только визуал.

### Жизни
3 на уровень (`startLives`), урон от шипов, врагов, пуль, босса, пилы, падения и раздавливания платформой. Инвулн. 90 кадров (1.5 с). Жизни не переносятся между уровнями.

### Враги
- `E` — 40×40, скорость 1.7, разворачивается у стены и на краю платформы (проверка `solidAt` впереди-внизу).
- `T` — стоит, смотрит на игрока, стреляет горизонтально, если `dx < 420` и `dy < 100`; первый выстрел через 60 кадров, потом каждые 90; пуля 10×8, скорость 4.5.
- Стомп: `player.vy > 0` и перекрытие по низу меньше 26 px → враг умирает, +5 очков, отскок.

### Платформы и ловушки
- `M` — 48×48, ход ±144 px по X, скорость 1.4; `V` — ±96 px по Y, скорость 1.0. Везёт игрока, при зажатии — урон («раздавило»).
- `O` — односторонняя: полоса 48×14 на 10 px ниже верха клетки, коллизия только сверху.
- `L` — падающая: 48×18 по центру клетки, дрожит 34 кадра, падает с ускорением 0.75, исчезает ниже уровня +200, возвращается через 150 кадров (если не перекрывает игрока).
- `B` — батут: 36×20 у низа клетки, сила −18.5, кулдаун 10 кадров.
- `R` — разрушаемый блок: ломается ударом головой снизу.
- `S` — шипы: урон по четырём прямоугольным зонам у треугольников, не по всей клетке.
- `W` — пила: ездит по X ±96 px, скорость 1.5, хитбокс с отступом 8 px.
- `N` — пушка: стреляет по горизонтали в сторону игрока при `dx < 460`, `dy < 120`; первый выстрел через 50 кадров, далее каждые 110; пуля 12×8, скорость 4.

### Предметы и выход
- `C` — монета 32×32 (+1 очко), покачивание.
- `K` — ключ 28×28; `D` — дверь высотой 96 px (две клетки вверх от символа `D`), открывается касанием при наличии ключа, ключ тратится.
- `F` — чекпоинт: активируется касанием, гасит остальные, респаун на его клетке.
- `X` — финиш 48×48; при живом боссе заблокирован.

### Босс
- `Z` → босс 88×88, стоит на нижней границе клетки, растёт вверх-влево.
- Здоровье: 3 (обычный), 4 (снежный = база+1), 5 (каменный = база+2); вторая фаза при `hp <= ceil(hp/2)`.
- Активация в радиусе 560 px, патруль ±288 px от старта.
- Скорости по фазам 1.15 / 1.85 от базы, у снежного +15 %, у каменного −5 %; прыжки, веер снарядов во второй фазе (обычный 3, снежный 5, каменный 3 снаряда), снаряды 14 px, жизнь 260 кадров.
- Урон только прыжком на голову; касание корпусом — урон игроку, верхней частью — мягкий отталкивающий «прощённый» контакт.
- При потере жизни босс возвращается на старт, полученные удары сохраняются (`R` сбрасывает бой целиком).

### Очки и звёзды
Монета +1, стомп +5, попадание по боссу +20, победа над боссом +100. Звёзды: 1 — пройден; 2 — все монеты **или** без потерь жизней; 3 — и то и другое.

## 5. Формат уровня

### Данные
`levels/levelN.js` — `const LEVEL_N = ["....", "...."]`. Метаданные лежат отдельно, параллельными массивами в `levels/levels-list.js`: `LEVELS`, `LEVEL_NAMES`, `LEVEL_BIOMES`, `LEVEL_BOSS_TYPES`. Автора и описания нет.

JSON своего уровня: `{ version: 1, name, rows: string[], biome, updatedAt, settings? }`. Паки пока не поддерживаются, но импорт уже терпит `{ levels: [...] }` и массив (берёт первый элемент).

### Символы (`TILE_CHARS` в `js/world.js`)
`.` пусто · `G` земля · `P` старт · `X` финиш · `C` монета · `E` враг · `T` стрелок · `S` шипы · `F` чекпоинт · `M` платформа → · `V` платформа ↑ · `K` ключ · `D` дверь · `B` батут · `L` падающая · `O` односторонняя · `R` разрушаемый блок · `H` лестница · `W` пила · `N` пушка · `Z` босс.

Клетка 48×48. Точная геометрия объектов (важно для валидатора и для документации):

| Символ | Занятая область внутри/вокруг клетки |
|---|---|
| `P` | 40×40, низ по низу клетки, сдвиг +4 px по X |
| `E`, `T` | 40×40, низ по низу клетки |
| `C` | 32×32 с отступом 8 px |
| `K` | 28×28 с отступом 10 px |
| `D` | 48×96: клетка `D` — нижняя половина, верхняя половина — клетка выше |
| `B` | 36×20 у нижней границы клетки |
| `L` | 48×18 по центру клетки |
| `O` | 48×14 на 10 px ниже верха клетки |
| `M`, `V` | 48×48, старт от клетки |
| `W` | 48×48, старт от клетки |
| `N` | 48×48, старт от клетки |
| `Z` | 88×88: от −20 px по X и от −40 px по Y |
| `X` | 48×48 |

Правила, которые движок применяет молча:
- строки разной длины дополняются точками, в консоль пишется предупреждение;
- неизвестный символ игнорируется (только предупреждение в консоль);
- нет `P` → старт в левом верхнем углу (48, 48);
- несколько `P` → побеждает последний;
- несколько `X` → работают все;
- несколько `Z` → побеждает последний (остальные исчезают);
- `K` без `D` бесполезны, `D` без `K` — непроходимая стена (если сверху `G`).

### Ограничения размеров
- Хранилище: ширина 8–120, высота 4–40, имя ≤ 40 символов.
- Редактор: ширина 10–120, высота 8–40 (расхождение с хранилищем — см. R7).
- Пиксельный размер карты: до 5760×1920.

## 6. `localStorage`

| Ключ | Содержимое | Кто пишет |
|---|---|---|
| `platformer.customLevels.v1` | массив `{id, name, rows, biome, updatedAt}` | `storage.js` |
| `platformer.testLevel.v1` | один уровень для `?test=1` | `storage.js` |
| `platformer.sound.v1` | `true/false` | `storage.js` |
| `platformer.levelSettings.v1` | `{ "builtin:0": {...}, "custom:<id>": {...} }` | `storage.js` |
| `platformer.progress.v1` | `{ levels: { "builtin:N": {...} }, stats }` | `progress.js` |
| `platformer.editorDraft.v1` | `{ name, rows, biome, levelId, updatedAt }` | `storage.js` |

Все чтения проходят через `try/catch`; битые данные заменяются дефолтом. Все ключи версионированы (`.v1`), менять формат без миграции нельзя.

Критично для доработок: `sanitizeLevel()` — белый список полей. Он **выбрасывает** любые новые поля (автора, описание), поэтому появление этих полей в редакторе обязательно требует правки `sanitizeLevel`, `saveEditorDraft`/`getEditorDraft`, экспорта/импорта и `getTestLevel`.

## 7. Редактор

Возможности (сверено с кодом):

| Блок | Что есть |
|---|---|
| Палитра | 21 клетка, у каждой название и цвет, `.` — ластик-пусто |
| Инструменты | кисть, ластик, прямоугольник (с заливкой), выделение, вставка; правый клик стирает |
| Выделение | копировать / вставить / вырезать / удалить, Ctrl+C/V/X, Delete |
| Отмена | стек 80 полных снимков карты, Ctrl+Z, Ctrl+Y, Ctrl+Shift+Z |
| Размер | ширина/высота с обрезкой и дополнением, без предупреждения о потере содержимого |
| Шаблоны | пустой, платформы, снег, замок, новые механики, башня, пещера, арена босса |
| Мини-карта | вся карта + рамка вида, переход кликом, «К старту», «К финишу» |
| Сохранение | в браузере, список готовых и своих, удаление, автосохранение черновика (500 мс), предупреждение при уходе |
| Файл | скачать JSON, загрузить JSON (в том числе из пака — берёт первый уровень) |
| Проверка | в новой вкладке, через `testLevel` |
| Валидация | ошибки: нет `P`, несколько `P`, нет `X`, несколько `Z`, неизвестные символы. Предупреждения: несколько `X`, нет `G`, `P` висит в воздухе, `D` без `K`, над `D` нет `G`, `Z` без земли, мало места над `Z` |

Слабые места редактора:
1. `validateLevel()` проверяет только **первую** дверь (`findTile("D")`), остальные не проверяются.
2. Уменьшение размера молча обрезает карту.
3. `undo()` после импорта JSON сбрасывает `importedSettings` — настройки из файла теряются, если отменить действие до сохранения.
4. Минимум ширины в редакторе 10, а хранилище принимает 8 — рассинхрон границ.
5. Нет полей автора и описания (задача подтверждена владельцем, см. §11).
6. Нет проверки достижимости финиша — только геометрия старта/двери/босса.

## 8. Страница настроек

- Список: готовые + свои; ключи `builtin:<index>` / `custom:<id>`.
- Ползунок + число для каждого поля, значения режутся по `min/max/step` из `EDITABLE_SETTINGS`.
- Пресеты: «Обычно», «Легко», «Сложно», «Луна» (заполняют поля, применяются по «Сохранить»).
- Хранятся только отличия от `DEFAULT_SETTINGS`.
- «Сбросить к обычным» удаляет ключ уровня.
- «Проверить в игре» сохраняет и открывает `index.html?level=N` / `?play=id`.
- `scale` позволяет показывать пиксели в клетках (дальность платформ).

Набор полей: гравитация, прыжок, число прыжков, скорость игрока, жизни, скорость врагов, батут, скорости платформ — основные; неуязвимость, стрелок (дальность, высота, пауза, скорость пуль, стартовая пауза), падающие платформы (дрожание, возврат), босс (здоровье, скорости фаз, стрельба, снаряды, прыжки), дальность платформ — расширенные.

## 9. Где физика и баланс

Единственный источник правды — `settings.js`: `DEFAULT_SETTINGS` (все числа), `EDITABLE_SETTINGS` (что можно менять и в каких границах), `SETTINGS_PRESETS`. `SETTINGS` — рабочая копия, в неё `applySettingsOverrides()` накладывает настройки уровня при `loadLevel()`.

Ключевые числа, которые нельзя менять без отдельного согласования: `TILE`, `FPS`, `gravity`, `jumpForce`, `playerMaxSpeed`, `maxJumps`, `startLives`, `invulnerabilityTime`, `enemySpeed`, `springForce`, `falling*`, `boss*`, `levelTransitionDelay`.

## 10. Прогресс, рекорды, достижения

`progress.js` пишет только для `levelSource === "builtin"`. Для каждого готового уровня: `completed`, `stars`, `bestTimeFrames`, `bestLives`, `startLives`, `bestCoins`, `coinsTotal`, `attempts`, `lastTimeFrames`, `lastStars`. Общая статистика: `deaths`, `attempts`, `completions`.

`TOTAL_CAMPAIGN_LEVELS = LEVEL_NAMES.length`; сантайзер перебирает индексы `0..TOTAL-1`, лишние записи отбрасываются. Добавление уровней 9+ безопасно: старые записи `builtin:0..7` сохранятся, новые начнутся с нуля.

Достижения (8): первый уровень, все монеты уровня, без урона, победа над боссом, все уровни, 50 монет, уровень быстрее 1:30, 15 звёзд.

Найдено по ходу:
- Уровень **без монет** не может получить 3 звезды: `allCoins = coinsTotal > 0 && ...`, значит максимум 2. Стоит зафиксировать правило явно (например, «нет монет — считаем allCoins=true») или в валидаторе требовать хотя бы одну монету.
- `countLevelCoins()` читает `LEVELS[index]` напрямую, а `TOTAL_CAMPAIGN_LEVELS` — из `LEVEL_NAMES`. Два источника правды для одного числа.

## 11. Решения владельца, принятые в этой сессии

1. Автор вписывает своё имя **в редакторе**; имя привязывается к уровню и показывается в списке уровней и на экране победы.
2. Строку «чем интересен уровень» тоже заполняют в редакторе; она сохраняется с уровнем.

Следствия для плана (без реализации на этапе 1):
- в `editor.html` появляются два поля в карточке «Уровень»: «Автор» и «Чем интересен» (одна строка, ограничение длины);
- поля проходят через `js/editor.js` → `js/storage.js` (`sanitizeLevel`, черновик) → JSON `{ author, note }`;
- старые JSON без полей импортируются как раньше (поля необязательные);
- `levels/levels-list.js` получает метаданные для уровней 1–8 и детей: `author`, `note`, `pack`;
- показ: список уровней (автор под названием), экран победы (автор + строка «чем интересен»);
- `README.md` дополняется описанием полей.

Открытые вопросы, не блокирующие этап 1: формат подписи (имя / имя и класс / ник) и показывать ли «чем интересен» игроку всегда или только на победе. Предлагаю: автор — как вписал ребёнок (свободный текст, с подсказкой «Имя, класс»), «чем интересен» — на экране победы, в списке — только автор.

## 13. Разбор детских уровней (`Пак_уровней(20.11.26)`)

Чинить: **старт (1,26) стоит на падающей платформе `L` над шипами** — через 34 кадра платформа исчезает и игрок падает в шипы; нужен `G` под стартом. Двери и ключи расположены так, что часть прохода может быть необязательной; проверить, что все 3 ключа достижимы, а 3 двери не запирают друг друга.

## 14. Технический долг и риски (для этапов 2–3)

1. Нет сборки, линтера, тестов и CI; всё в глобальной области, ~200 имён, порядок `<script>` критичен.
2. Каждый новый уровень — правка 3 HTML-файлов и 4 параллельных массивов.
3. Нет валидатора как отдельного слоя: проверки живут в `editor.js` и работают только в редакторе; игра принимает что угодно.
4. Нет миграций: формат версионирован, но кода миграции нет — при смене формата придётся писать вручную.
5. Отрисовка без отсечения: на карте 120×40 рисуются все клетки (до 4800 `drawImage` за кадр), плюс враги и частицы. Для детских карт важно (этап 7).
6. `solidAt()` — линейный поиск по всем твёрдым клеткам для каждого врага каждый кадр; на больших картах это O(n·m).
7. `sanitizeLevel()` — белый список полей: любое новое поле молча теряется. Точка расширения для автора/описания.
8. Двери проверяются только первой; несколько `Z`/`X` движок обрабатывает молча.
9. Границы размеров расходятся между редактором и хранилищем.
10. Уровень без монет не может получить 3 звезды.
11. `README` местами устарел (R1–R12) — привести в порядок после этапа 4.
12. Нет доступа с телефона, фиксированный холст 960×540 — этап 7.

## 15. План этапа 2 (каркас) — на подтверждение

Цель: Vite + ES-модули + ESLint + Vitest + GitHub Actions. Игра и редактор работают как раньше, поведение не меняется, ключи и форматы `localStorage` не трогаем.

1. **Ветка** `stage-2-scaffold` от `main`.
2. **package.json**: `vite`, `eslint`, `vitest` (только dev), скрипты `dev`, `build`, `preview`, `test`, `lint`. Версии фиксируем в `package-lock.json`.
3. **Vite, multi-page**: `index.html`, `editor.html`, `settings.html` — входные точки; `sprites/`, `css/` — статика; `base: "./"`, чтобы сборка открывалась с любого пути.
4. **Модули**: механический перенос в `src/`:
   - `src/core/` — `settings.js`, `storage.js`, `sound.js`, `canvas.js`, `input.js`, `effects.js`, `progress.js`;
   - `src/game/` — `world.js`, `player.js`, `enemies.js`, `boss.js`, `render.js`, `game.js`;
   - `src/editor/` — `editor.js`;
   - `src/settings/` — `settings-page.js`;
   - `src/data/levels/` — `level1..8.js` + `index.js` (реестр с `name`, `biome`, `bossType`).
   Логику не переписываем: только `export`/`import`, никаких новых абстракций.
5. **Состояние**: на этом этапе оставляем мутабельные массивы, но собираем их в один модуль `src/game/state.js` (объект-контейнер), чтобы убрать неявный глобальный обмен между модулями. Это самая рискованная часть — делается отдельным коммитом и проверяется руками.
6. **ESLint**: flat config, `no-unused-vars`, `no-undef`, `eqeqeq`, `no-var`; правило стиля — 2 пробела, как в текущем коде. Без автоформата, чтобы не раздувать дифф.
7. **Vitest**: первые тесты на то, что уже детерминировано — `sanitizeLevel`, `normalizeLevelRows`, `sanitizeSettingsOverrides`, `calculateLevelStars`, `formatTimeFrames`, реестр уровней (8 уровней, у каждого имя и биом).
8. **GitHub Actions**: `npm ci` → `npm run lint` → `npm test` → `npm run build`, артефакт `dist`.
9. **Проверка руками** по чеклисту: меню, «Продолжить», выбор уровней и звёзды, все 8 уровней до финиша, три босса, пауза, проигрыш, финал, «Мои уровни», редактор (шаблоны, undo, сохранение, загрузка, экспорт, импорт, проверка), настройки (пресеты, сохранение, сброс, проверка в игре), сохранность старых ключей `localStorage`.
10. **README**: раздел «Как запустить» меняется на `npm install` / `npm run dev` / `npm run build`; добавляется пометка, что прямой `file://` больше не поддерживается.
11. **Коммиты**: `chore: каркас Vite`, `refactor: модули ядра`, `refactor: модули игры`, `refactor: редактор и настройки`, `test: базовые тесты`, `ci: проверки GitHub Actions`, `docs: README про сборку`.

Риски и как снимаем:
- порядок инициализации модулей — переносим по одному слою, после каждого шага ручная проверка;
- циклические импорты (мир ↔ игрок ↔ рендер) — выносим общее состояние в `state.js`, иначе ESM упадёт на `undefined` при загрузке;
- старые ссылки `?test=1`, `?play=`, `?level=` — сохраняем как есть;
- `localStorage` — ключи и форматы не меняем, проверяем на сохранённых данных до и после.
