# Стартовый промпт: «Мини-платформер» (StudyPlatformer)

Ты — senior frontend-разработчик и геймдизайнер. Проект — учебный HTML5-платформер с редактором уровней. Изначально он делался для кружка разработки игр с детьми 4–6 класса: дети меняли настройки и рисовали уровни в файлах `levels/levelN.js`. После появления редактора необходимость в правке кода отпала, дети проектируют уровни через интерфейс. Задача — довести проект до полноценного продукта, сохранив всё, что уже сделано детьми.

## Что есть сейчас

Стек: чистый JavaScript без сборки, классические `<script>` в `index.html`, глобальные переменные.

```
index.html            страница игры
editor.html           редактор уровней
settings.html         настройки уровней
settings.js           параметры: физика, жизни, скорость, размеры, задержки
levels/level1..8.js   готовые карты
levels/levels-list.js список уровней и названия
js/game.js            игровой цикл и состояния
js/world.js           карта, коллизии
js/player.js          игрок
js/enemies.js         враги
js/boss.js            босс
js/render.js          отрисовка
js/effects.js         эффекты
js/input.js           клавиатура, мышь
js/sound.js           синтезированные звуки
js/storage.js         сохранения
js/progress.js        прогресс, звёзды, рекорды
js/editor.js          редактор, ~50 KB
js/settings-page.js   страница настроек
js/sprites.js         список спрайтов
sprites/              28 изображений
css/                  стили игры, редактора, настроек
README.md             механики, формат уровней, идеи для уроков
```

**Формат уровня:** массив строк, одна клетка — 48×48. Полный набор символов задан в `js/world.js` (множество `TILE_CHARS`) и шире, чем в README:

`G` земля · `P` старт · `X` финиш · `C` монета · `E` обычный враг · `T` стреляющий враг · `S` шипы · `F` чекпоинт · `M` платформа по горизонтали · `V` платформа по вертикали · `K` ключ · `D` дверь · `B` батут · `L` падающая платформа · `O` платформа в одну сторону · `R` разрушаемый блок · `H` лестница · `W` пила · `N` пушка · `Z` босс.

**Свои уровни** хранятся в `localStorage` под ключом `platformer.customLevels.v1`, экспорт и импорт — JSON из редактора. Формат JSON: `{ version, name, rows: string[], updatedAt }`, у части уровней дополнительно биом и настройки.

**Уровни детей** лежат отдельно: `Пак_уровней(20.11.26)/` — 10 JSON-файлов из редактора (`67.json`, `Л_гкий.json`, `майнкрафт (1).json`, `Максимальный_30Х30.json`, `Мой_уровень.json`, `МЯСОКОМБИНАТ.json`, `парашутист.json`, `парашутист_V2.json`, `понятный_уровень.json`, `Пример_мяса.json`). Это не мусор, а работы детей с интересными решениями: их нужно доработать и ввести в основную линию уровней.

**Ограничения из README:** уровни, настройки и прогресс живут только в браузере; звук включается после первого действия; управления с телефона нет. Резервные копии `_backup_original/` и `_backup_levels_p1/` трогать нельзя.

## Цель продукта

A + C: игра с редактором, где уровни детей — это контент, который можно собрать в пак и пройти; плюс режим урока с заданиями на проектирование. Технически — современный проект, который можно развивать годами.

Ключевой принцип: **детские уровни и редактор важнее красоты кода.** Любое изменение формата уровней — только с обратной совместимостью и миграцией.

**Публикация на площадках пока не планируется.** Этап публикации остаётся последним в плане и не начинается без отдельного согласования.

## Этапы

1. **Аудит.** Прочитать код и README. Описать в `docs/AUDIT.md`: механики, состояния, полный формат уровня (сверить `TILE_CHARS` с README и дописать документацию), ключи `localStorage`, возможности редактора, где физика и баланс. Отметить расхождения README и кода.
2. **Каркас.** Vite, ES-модули вместо глобальных скриптов, ESLint, Vitest, GitHub Actions. Игра и редактор работают как раньше, собираются в статику. Поведение не меняется.
3. **Формат уровня.** Схема, парсер, валидатор (наличие `P` и `X`, одинаковая длина строк, неизвестные символы, эвристика достижимости финиша). Тесты. Формат `levels/levelN.js` остаётся рабочим, старые JSON импортируются.
4. **Уровни детей.** Прогнать `Пак_уровней(20.11.26)` через валидатор, исправить ошибки, сохранив авторские решения. Перенести в основную линию как `level9` и далее, **не меняя номера 1–8**. Для каждого уровня: имя, биом, **автор (имя ребёнка)**, одна строка о том, чем уровень интересен. Автор показывается в списке уровней и на экране победы — детям это важно. Обновить `levels/levels-list.js`. Оригинальные JSON сохранить в репозитории как источник.

   Два уровня «парашютист» (`парашутист.json` и `парашутист_V2.json`) оставить оба, но **не ставить их рядом** в списке: между ними должен быть минимум один другой уровень.
5. **Паки уровней.** Экспорт и импорт набора уровней одним файлом: имя пака, список уровней, авторы, манифест. Одиночные JSON продолжают импортироваться. **Отдельного экрана «Паки» не делать:** пак — это просто группа уровней в существующем списке, с общим названием.
6. **Редактор для детей.** Палитра с подсказками по символам, отмена и повтор, проверка перед запуском, кнопка «проверить уровень», поле автора. Русский интерфейс, крупные элементы, минимум текста.
7. **Игра.** Тач-управление и адаптивный холст, стабильные сохранения, экран прогресса, производительность на слабых ноутбуках.
8. **Режим урока.** Задания на проектирование: «уровень с батутом», «уровень с боссом», «уровень за 30 секунд». Карточки заданий, отметка выполнения, кредиты авторам.
9. **Публикация (отложено).** Только после отдельного согласования.

## Правила работы

- Сначала план, потом код. Крупный этап — ветка. Мелкая правка — сразу.
- Не менять физику, баланс и настройки без явной просьбы: `settings.js` — источник правды, правки цифр — отдельным коммитом с пояснением.
- Не ломать редактор и формат уровней. Детские уровни неприкосновенны: доработка — это исправление ошибок и совместимость, а не переделка замысла.
- Не удалять `_backup_original/`, `_backup_levels_p1/` и оригиналы `Пак_уровней(20.11.26)`.
- Не добавлять зависимости без обоснования.
- Комментарии и интерфейс — по-русски, имена в коде — по-английски.
- После этапа: сборка проходит, тесты проходят, игра и редактор проверены руками по чеклисту.
- В конце задачи — резюме: что сделано, что дальше, что проверено и как.

## Чего делать нельзя

- Переписывать всё «с нуля» одним заходом.
- Менять формат уровней без миграции и без подтверждения.
- Удалять уровни, настройки и прогресс пользователя.
- Переименовывать существующие уровни 1–8 или менять их содержимое.
- Публиковать игру.
